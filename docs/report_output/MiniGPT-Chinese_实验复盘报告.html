1. 结论摘要（TL;DR）

3.792 → 钉死
实验1：真过拟合（数据少 + slide 重复曝光）
4.277 ≠ 退步
实验2：换了 token 空间，数值不可比，过拟合已消失
3.636 · gap 0.02
实验3：调度修复后到位，当前无过拟合
三条主线判断 ① 实验1 的 val 三连钉死是真过拟合：20M token 太少，叠加 slide stride=1 让每个 token 在一个 epoch 内被高度相关地重复看 128 次，模型记住训练片段、迁移不到未见的书。
② 实验2 的 4.277 不是模型变差：词表 3256→6144、语料、采样模式、上下文同时更换，交叉熵换了目标分布，数值尺度不可横比；它真正的结论是 gap≈0.02，过拟合被数据与 pack 消除，矛盾转为容量/训练不足。
③ 实验3 第一阶段的 4.021 不是容量极限，是 cosine 在 E1 末衰减到 0 造成的伪收敛；resume 做 warm restart 后一路降到 3.636，最终 gap≈0.02。
当前所处位置 20.11M 参数 / 400M token = 19.9 token/param，恰好压在 Chinchilla 20:1 的计算最优线上；E5–E6 连续持平说明在「容量 20M / 上下文 256 / 数据 400M」三轴同时锁定时到达收益递减点。要继续降 loss，必须松开轴，且容量与数据要按比例一起松，单独加一个会走向过拟合或浪费。

推荐路线：先用三个单变量实验（A 容量 / B 上下文 / C 数据）定位第一瓶颈，再做组合实验 Exp5，落点 35–41M + block512 + 0.7–1B token；上下文翻倍时 batch 减半以保持 tokens/update=65536；固定复用 6144 分词器保证跨实验可比；用已修复的 min_lr_ratio=0.1 杜绝伪收敛。

2.2 训练管线关键机制（train/train.py）

  • 优化：AdamW，lr=8e-4，weight_decay=0.05；warmup 500 步 + cosine（当前版本 min_lr_ratio=0.1，底部不归零）；AMP 混合精度；grad_clip=1.0。
  • 过拟合口径：每次验证额外在训练集随机子集上以 eval 模式（关 dropout）算 train_eval，报告 gap = val − train_eval —— 这是正确指标，训练时的 EMA/epoch 均值带 dropout 噪声，不能直接与 val 相减。
  • 数据：按「真书」90/10 划分（修复了顺序切分把整本书落入验证集、高估 loss 的早期 bug）；pack 模式零拷贝视图；缓存名含词表/采样量/语料长度，任一变化自动失效。
  • 续训：checkpoint_best 为纯推理权重，checkpoint_latest 为含优化器/AMP/step 的完整续训包；resume 时 cosine 按新总步数重锚（warm restart）。
「当前代码 ≠ 完整历史」的三处具体体现 1）当前默认 sample-mode 已偏向 pack，实验1 的 slide 路线只作为选项保留；2）当前 tie_embeddings 默认开启，而参数量反推显示实验1 当时未做权重共享（见 9.1）；3）当前 cosine 默认保留 10% 底学习率，实验3 第一阶段「衰减到 0」的状态已被修复。历史结论必须结合实验记录解读，不能只看现版本代码。

4. 逐轮深度复盘：为什么变、loss 为什么这样走

4.1 实验1：最小闭环跑通，但撞上「小数据 × 重叠滑窗」的真过拟合

为什么这样配置

目标是先打通「语料→BPE→模型→生成」全链路。slide stride=1 是教科书式标准切法（每个起点一个样本），在小语料上能制造大量样本、梯度更平滑；batch=512 的大 batch 也利于初期稳定。这是工程验证导向的合理起点，不是为规模化准备的。

loss 现象与机制

E0 train 3.550 / val 3.792，到 E2 train 3.286 而 val 3.794：train 单调下降，val 三个 epoch 几乎不动（3.792/3.792/3.794）。机制有两层：

  • 数据相对参数太少：仅 20M token 供养 6.3M 参数，独立信息量不足，模型开始记忆训练集的局部 token 共现；
  • slide stride=1 放大重复曝光：每个 token 会出现在 block_size=128 个窗口里，同一段文本在一个 epoch 内被高度相关地重复学习 128 次，「窗口数 ≈2000 万」是假象，有效独立样本量远小于窗口数，进一步鼓励死记。验证集是没见过的书，背下来的局部统计迁移不过去。

于是 train 持续下行、val 原地踏步，gap（训练口径）由 0.242 走阔到 0.508。

判定：真过拟合（高方差）三件套同时成立——train↓、val 平/微↑、gap 持续走阔。不是欠拟合，因此对症的药是「更多独立数据 + 降低重复曝光（pack）」，而不是加大模型（加大只会更过拟合）。

4.2 实验2：一次工程换轨，4.277 是「新赛道的起点」而非退步

为什么一次改这么多

这一步的性质是基础设施升级而非单超参调优：语料扩到 120M 后，slide stride=1 的每-epoch 步数≈token 数（千万级），CPU/IO 无法承受，必须改 pack（每 token 每 epoch 只看一次，步数降到约 1/block）；同时把词表扩到 6144 以提升中文覆盖与压缩，block 128→256 提升连贯性。多变量同换在「换基建」时可以接受，但代价是 loss 不能与实验1 对照。

为什么数值反而「更高」

  • token 空间变了：vocab 3256→6144，随机基线从 ln3256=8.09 抬到 ln6144=8.72；分词粒度改变后，同一句中文被切成不同的 token 序列，交叉熵是对不同目标分布求期望，数值尺度天然不同；
  • 任务分布变了：语料从 20M 扩到 120M 且覆盖更广，难度分布不同；
  • 梯度相关性变了：block 变大、pack 不重叠，单步梯度的统计结构不同于 slide。

真正有价值的信号：过拟合消失

E0 train/val=5.475/5.479、E5=4.258/4.277，gap 仅 0.004 / 0.019，两条线几乎重合且一起在降。这说明数据侧不再稀缺，模型来到「数据充足、容量与训练量不足」的一侧（未训透/偏欠拟合）。此时正确动作是加容量、加训练、继续加数据，而非加正则。

记录缺口（不臆造）实验2 仅留存 E0、E5 两个点，E1–E4 曲线缺失，本报告不做插值；4.277 止步于容量与训练时长，不能归因于数据。

4.3 实验3：扩容见效，但先被调度「假收敛」绊了一下

为什么扩到 20M / 400M

实验2 已证明矛盾不在过拟合、而在容量与训练充分度，于是参数 6.3M→20M（10 层/d384）、数据 120M→400M，继续 pack、词表与上下文保持不变（保证与实验2 同尺度可比）。

第一阶段 4.021 停滞：根因是 cosine 提前归零

E1 结束 train 4.005 / val 4.021 后不再下降。根因是 cosine 按第一阶段设定的总步数在 E1 末衰减到了 0，有效学习率≈0，参数几乎停止更新，loss 被「冻」在当前值。这是优化器调度问题（伪收敛/假平台），不是模型容量到顶，也不是数据耗尽。

resume / warm restart 为什么能救回来

--resume 恢复权重、优化器、AMP 与 step，同时 cosine 按新的总 epoch 重新锚定，学习率从底部重新拉起，给模型逃离平台区的「二次动量」。随后 E2 3.701 → step25k 3.687 → E3 3.647 → E4 3.636，累计再降 0.385。

最终形态解读

  • E5–E6 连续持平 3.636，train_eval 3.616，gap≈0.020 且很小 → 没有过拟合；
  • 但连续两轮不降 → 在「20M / 256 / 400M」三者锁定下到达收益递减点；
  • 用 Chinchilla 回看：400M ÷ 20.11M = 19.9 token/param，正好落在 20:1 最优线上——当前不是单纯「模型太小」或「数据太少」，而是参数与数据同时到达互相匹配的边界。

5. 过拟合 / 欠拟合 / 伪收敛判据体系

用四个可观测联合判断：train_eval 趋势、val 趋势、gap = val − train_eval、当前 lr。

状态train_evalvalgaplr对症动作
健康下降↓↓稳定且 ≤0.05正常继续训练
过拟合（高方差）持续 ↓平 / ↑走阔 >0.05正常加数据、降模型、加 dropout、减少重复曝光
欠拟合 / 未训透（高偏差）都偏高且一起 ↓极小正常加容量、加训练时长、适当提 lr
伪收敛（调度故障）平台不动小≈0修 scheduler / warm restart，勿误判为容量极限
收益递减（到配置边界）低位连续 2–3 次验证不动小正常改轴：扩数据 / 扩容量 / 扩上下文

5.1 三种 loss 形态示意（依据本项目真实曲线归纳）

过拟合（实验1）

train 下行、val 水平，gap 越拉越大。

健康（实验3）

两条线一起降、始终贴近，gap≈0.02。

伪收敛→重启（实验3一阶段）

平台是因 lr 归零；重启后继续降。

示意（非逐点拟合）：train / train_evalval 过拟合val 健康val 伪收敛

口径纪律① 必须用 eval 模式（关 dropout）在 train/val 的同分布随机子集上算 gap（代码已实现 train_eval）；训练时 EMA、epoch 平均都带 dropout 噪声且是滑动量，直接减 val 会虚高——实验1 历史数字即训练口径，会偏大，但「走阔」方向不变。② 跨实验比较请固定同一验证子集与随机种子，否则验证抽样噪声会制造「假改善/假恶化」。③ PPL=exp(loss)（当前 37.9）只在同词表下可比。

7. 下一阶段受控实验设计

7.1 统一纪律（每个实验都遵守）

  • 一次只动一个轴；固定复用现有 6144 分词器（tokenizer_best.pkl）编码新语料，保证 loss 尺度可比；
  • 固定同一验证子集与随机种子；每轮记录 train_eval / val / gap / lr 四元组；
  • total_steps = steps_per_epoch × epochs 按 pack 实际步数重算，cosine 用 min_lr_ratio=0.1，不再衰减到 0；
  • 以当前 3.636 为对照锚点，每个实验预先写明「通过 / 否决」判据与停止条件。

8.2 分轴建议

  • 上下文（优先、独立）：256→512 先做，batch 256→128 保持 tokens/update=65,536（256×256 与 128×512 经复算完全相等），稳住梯度噪声尺度；512 在 4090 + SDPA 可行，1024 因 O(T²) 与激活显存需先评估。
  • 模型形状：优先「加宽 + 适度加深」，d=512、8 头时 head_dim=64 规整；暂不建议先动头数。ReLU→GELU 这类改动会引入新变量，如要尝试须单独消融，不要与扩容混跑。
  • 优化器 / 正则：35M+ 若初期不稳，lr 8e-4→6e-4、warmup 维持 500；gap 走阔再把 dropout 0.1→0.15，若 gap≈0 反而可降到 0.05；weight_decay 0.05 维持。
  • 词表：固定 6144 复用，保障跨实验可比；仅当新语料压缩率明显恶化、OOV 飙升时，才把「扩词表」作为独立轴——历史已证明换词表会让旧 loss 全部失去可比性，代价高。
  • 调度铁律：按 pack 实际步数设 total_steps，cosine 保留 10% 底（已修复），warm restart 只作补救；杜绝再次出现「4.021 伪收敛」。
  • 数据卫生：坚持按真书 90/10（prepare_webnovel 已实现），防止整本书落入验证集高估 loss；新旧语料混配要记录比例。
一句话路线先并行排期 B（上下文，成本最低）与 C（数据扩到 ~1B），用 A（35M 压 400M）做诊断性压力测试；三者结论汇合后，Exp5 落 35–41M + block512 + 0.7–1B，token/param 控制在 20–28，稳扎稳打突破 3.636。

9. 附录：公式推导、证据与口径

9.1 参数量公式（tie 共享、8 头、FFN=4d）

每层参数 = 注意力 4·(d²+d) + FFN (8d²+5d) + 两个 LayerNorm (4d) = 12d² + 13d 总参数 P = V·d + L·(12d²+13d) + 2d + V （V·d 为共享嵌入，仅计一次；2d 为最终 LN；V 为输出偏置）
  • 代入 d=384, L=10, V=6144 → 20,110,848，与 checkpoint 实测一致（交叉验证通过）；
  • d=256, L=6, V=6144 → 6,318,080（6.3M，对应实验2）；
  • 同结构 V=3256 → 5,575,864；若不做 tie 需再加输出头 3256×256=833,536，得 6,409,400≈6.3M —— 与实验1 标称 6.3M 吻合，据此推断实验1 早期未做权重共享（推断，非代码直接证据）。

9.2 关键复算

  • tokens/update：256×256 = 65,536 ＝ 128×512（上下文翻倍、batch 减半时守恒）；
  • token/param：400,000,000 / 20,110,848 = 19.89；1,000,000,000 / 34,676,736 = 28.84；
  • 随机基线 ln(3256)=8.088、ln(6144)=8.723 nats；当前 PPL = e^3.636 = 37.94。
